## Known Drizzle Issue: Partial Index WHERE Clause Migration Bug

Drizzle Issue #3349 — partial unique index WHERE clause emits `$1` placeholder instead of
column name in generated migration SQL. Unresolved as of August 2025.

**Why:** Drizzle parameterizes column references differently in migration contexts vs runtime.

**How to apply:** After running `drizzle-kit generate`, always inspect the output SQL to
verify the WHERE clause contains the column name (e.g., `WHERE \`deleted_at\` IS NULL`),
not `WHERE $1`. If `$1` appears, switch `.where(sql\`${table.deletedAt} IS NULL\`)`to`.where(sql\`deleted_at IS NULL\`)` and regenerate.

## drizzle-zod + zod v4 — Deferred

`drizzle-zod v0.8.1` added Zod v4 support but has reported issues with the `./v4` specifier
and branded types. The project uses `zod@^4.0.0`. Do NOT install `drizzle-zod` in M2 Task 1.
Evaluate in Task 3 and fall back to hand-written Zod schemas from `$inferInsert`/`$inferSelect`
types if needed.

## M2 DB Module Structure

```
app/lib/db/
├── client.ts    — libSQL singleton, server-only, fail-fast env validation
├── schema.ts    — sqliteTable definition, exports Furigana and NewFurigana types
└── queries.ts   — typed query functions (Task 3, depends on client + schema)
```

## client.ts Env Validation Rules

- `TURSO_DATABASE_URL` empty or undefined → throw always
- `TURSO_AUTH_TOKEN` undefined AND URL does NOT start with `file:` → throw
- `TURSO_AUTH_TOKEN` undefined AND URL starts with `file:` → allowed (pass `authToken: ""`)
- `TURSO_AUTH_TOKEN` empty string → allowed for both file: and remote URLs

## Migration Directory

`drizzle/` at repo root — must be committed to git (not gitignored).
Generated by `pnpm exec drizzle-kit generate`.
Use `dialect: "turso"` in `drizzle.config.ts`.
